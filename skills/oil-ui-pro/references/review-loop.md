# 评审循环与扩展派发

主 Agent 专用，是 [视觉评审派发协议](visual-review.md) 的补充。视觉评审的交接清单和反馈处理照那份文件执行；开放式 UX 走查按下方专段，其他评审轮次和类型按本文件。各种评审的标准在 [评审手册补充](review-modes.md)，由子 Agent 读，主 Agent 不读。

## 评审轮次

**打分循环制**（针对全新设计）：以 9 分为完成目标，最多 3 轮。每轮都派全新的子 Agent，但第一轮之后不再从头挑毛病，否则每轮都冒出新问题，循环收不住，分数的涨落也说明不了修改有没有用。

1. **第一轮盲审**：按派发协议交接，评审给出排好序的问题、提升条目、“保留”一行和分数。
2. **之后的轮次先复核**：改完只重新截这一轮改动影响到的画面和动效，派全新子 Agent，交给它新截图和上一轮的问题与提升清单，清单连同“保留”一行原样转交，不给分数，也不附你的修改说明。提示词用下表的复核模板。复核逐条判断修好、修了一部分还是没修，最多再指出 3 处这批修改带来的新问题，然后重新打分。只有某项结论因缺少画面无法判断时，才补那一项的图或录屏，不因换了评审者就重取整套证据。
3. **什么时候换回盲审**：复核里全部修好、分数仍不到 9，说明剩下的差距第一轮没指出来，下一轮派全新盲审，拿一份新的问题清单。评审第一条写“重做”时，按派发协议回到方向卡重做，下一轮也用盲审。新盲审沿用未受改动影响的证据，不把换评审者当作重新取证的理由。
4. **停止**：满 9 分；或到 3 轮；或同一条问题连续两轮复核都没修好，这时停下，在交付说明里写清卡在哪里、试过什么改法。证据数量不足、想增加覆盖却不是具体可复现的问题，不构成继续一轮的理由。

- **到了 9 分就收尾交付**：达到停止条件后，不用再把剩下的提升条目全做完；顺手能改、不动结构的可以一并改掉，其余写进交付说明交给用户决定。

## 开放式 UX 走查

在 [轻量 UX 走查派发](ux-review.md) 的基础上，Pro 追加自主风险探针和一次同路径复核。默认触发条件、交接材料、独立执行证据、主 Agent 复现与功能验证照那份文件执行，不在这里重复。

**第一轮在轻量主路径后深化。** 提示词用：

`请读取 references/review-modes.md，按照【任务走查】的【开放探索】执行。先完成轻量主路径，再自主选择一个相关风险点检查，记录实际观察到的体验障碍。页面地址、视口和必要测试材料如下。`

**修改后只复核一轮。** 派一个全新的 UX 子 Agent，给当前页面和上一轮报告，让它沿上一轮已经发生的同一路径逐条核对，并检查这批修改造成的直接副作用；这时给路径是为了复核，不再称为开放探索。提示词用：

`请读取 references/review-modes.md，按照【任务走查】的【复核】执行。对照附上的上一轮报告复走同一路径，逐项判断修好、修了一部分还是没修，再检查这批修改直接引入的问题。`

复核必须沿同一路径真实点击，完成必要的连续操作，不能只对照截图。没有修改就不复核；复核后仍没修好的写进交付说明，不换 persona、不加新案例重新挑一轮。UX 子 Agent 的报告不能替代主 Agent 在步骤 5 的功能验证；保存后的读回和失败后的恢复仍须实际执行，不因减少截图而省略。它能发现可观察的操作障碍，但不代表真实用户，也不据此推断真实用户成功率、满意度或耗时。

## 复核、多方向、任务走查与方案评审

| 你做了什么改动 | 子 Agent 的提示词 (Prompt) 模板 |
| --- | --- |
| 打分循环第二轮起，复核上一轮的问题和提升 | `请读取 references/review-modes.md，按照【复核】标准，对照附上的上一轮问题与提升清单检查这些新截图，然后重新打分。` |
| 几个方向都做成了完整页面，或用户要求评审几个首屏 | `请读取 references/review-modes.md，按照【多方向横向对比】标准，检查提供的多张方向截图是否属于同一骨架换皮。` |
| 涉及业务流程或交互链路的更改 | 按上面的“开放式 UX 走查”派发，不在提示词里另写具体任务。 |
| **评审改流程和加新功能的方案**：改流程或加新功能出了几个方案 | `请读取 references/review-modes.md，按照【改流程与加新功能方案评审】标准，比较提供的几个方案，指出假差异、补丁和每个方案最可能失败的场景。` |

模板里的路径按 [派发协议](visual-review.md) 换成绝对路径。

小游戏、抽奖、计时养成这类产品，派发全新界面评审时在提示词末尾加一句：`另按 references/play-craft.md 的“交付和评审时多查几项”核对。`
